# ADR 001：父任务聚合状态由执行任务派生

- 状态：已废弃（由 ADR 005 取代）
- 日期：2026-08-28

## 背景

团队父任务固定停留在“待规划”，实际进展由管理员分派出的成员执行任务分别推进。父任务不能再保存一个可被客户端直接编辑的状态，否则会与成员副本产生冲突，也会让报告和审计失去唯一事实来源。

## 决策

父任务的 `aggregateStatus` 只在读取投影时由当前可见的执行任务计算，不写入任务状态，也不接受客户端写入普通流转状态。唯一例外是创建人或空间管理员可将父任务拖入“已取消”，且必须填写原因。取消是终态，不可恢复。`aggregateUpdatedAt` 取这些执行任务轨迹中最新的有效时间（优先 `history[].at`，其次 `recordedAt`）。

聚合规则按以下顺序确定，规则与输入顺序无关：

1. 没有可见执行任务：`planned`。
2. 任一执行任务为 `blocked`：`blocked`。
3. 否则任一执行任务为 `in_progress`，或部分执行任务已完成、仍有任务未进入终态：`in_progress`。
4. 否则任一执行任务为 `todo`：`todo`。
5. 否则任一执行任务为 `planned`：`planned`。
6. 剩余任务均为终态时，只要存在 `done` 就为 `done`；全部为 `cancelled` 才为 `cancelled`。

阻塞和正在推进的工作优先暴露，避免“全部完成”掩盖仍需处理的成员任务。管理员看到完整执行任务集合；普通成员的聚合仅基于其权限可见的执行任务，不通过聚合字段泄露不可见成员信息。

## 结果

- 父任务仍只能由管理员创建、分派和编辑；除取消外，持久化状态始终为 `planned`。
- 取消父任务时，未完成的执行任务自动取消并记录父任务取消原因；已完成执行任务保留完成事实，并标记所属父任务已取消。
- 看板分栏、统计、卡片和详情使用聚合状态，并显示成员状态与最新成员轨迹时间。
- 成员执行任务的状态、顺序、轨迹和进度仍分别保存，聚合值可随读取即时更新。
- 颜色只作为低饱和提示，界面同时显示文字状态，避免颜色成为唯一语义。

该设计属于旧版“团队父任务 + 成员执行副本”模型。现行模型将父任务和成员任务
统一为独立 Issue，父子状态不互相聚合，详见 [ADR 005](./005-multica-workspace-domain.md)。
